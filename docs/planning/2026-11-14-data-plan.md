# Data plan (data engineer, 2026-11-14)

How Trend Detective gets its data, where it lives, what the statistics team can call, and what is
still to do. Complements [plan v2](2026-11-14-plan-v2.md) (product, JSON contract) and
[stats methods](2026-11-14-stats-methods.md) (what is computed). Status: **draft for team review**.

## 1. Role in plan v2

Plan v2 makes the site fully static: Python precomputes every number into JSON (`public/data`), the
site only draws it. The data engineer sits at the start of that chain:

```
NASA archives ──► data engineer ──► data/cache (series, grids, provenance) ──► build_all.py (stats) ──► public/data JSON ──► site
```

The data engineer delivers **inputs**: monthly and daily regional series, global grids for the map,
and the variable catalog. The statistics team turns them into `analysis.json` and `map.json`.
No data engineering code runs in the deployed site, and no Earthdata token is ever needed there.

## 3. Where data lives

| Layer | What | Where | In git | Size now | Size at the end |
|---|---|---|---|---|---|
| L0 | NASA archives | NASA / AWS | no | TB | — |
| L1 | raw downloads (GRACE file) | `data/cache/raw/` | **no**, rebuilt by scripts | 45 MB | < 1 GB |
| L2 | regional series (CSV) + `.provenance.json` | `data/cache/{power_zarr,earthdata}/` | **yes** | 7 MB (72 series) | ~10 MB |
| L2 | global grids for maps | `data/cache/grids/` | only map grids (D2) | 26 MB (T2M, 2°) | 26 MB per map variable |
| L3 | `analysis.json`, `map.json`, `index.json` | `public/data/` | yes | — | owned by the stats team |

Sharing: colleagues get everything through `git pull`. No cloud storage, no shared drive. Earthdata
series are committed, so nobody else needs a token.

**Data freeze rule.** The data is committed and frozen: the data engineer fetches, everyone else only
pulls, so every teammate and `build_all.py` see identical numbers. A refresh is a deliberate commit
(`data: refresh POWER to 2026-10`) and updates `data/cache/MANIFEST.json` (file, sha256, freeze date).
Refetching on each machine is not used: POWER adds and reprocesses months, so different fetch days
would give different slopes, and Earthdata series would need a token per person. Only if map grids
grow beyond ~100 MB do they move to a GitHub Release; the series stay in git.

CSV formats:
- monthly: `month,value` (NDVI adds `valid_fraction`), month = first day of the month
- daily: `date,value`
- units are the source units, recorded in the provenance file

## 4. What the statistics team calls

All in `backend/trend_detective/acquire.py`:

| Function | Returns | Use |
|---|---|---|
| `list_variables(available_only=False)` | catalog entries with `available`, `live`, definitions | `catalog.json` |
| `list_regions()` | presets from `data/catalog/regions.yaml` | `index.json` regions |
| `get_series(variable_id, region)` | monthly series; `attrs`: catalog summary, provenance, `assessment` | S1, S3, S5 |
| `get_input_series(parameter, region, store="merra2_daily")` | any POWER parameter, monthly or daily | method inputs (M2, M6) |
| `get_monthly_from_daily(parameter, region, how)` | monthly from daily, ≥ 80% of days (S2); `attrs["aggregation"]` | M3 (SPEI), `qc.aggregation` |
| `assess(series)` | `ok` / `caution` / `too_short` / `no_variation` + plain-language notes | `qc`, verdict `insufficient` |
| `inventory(region)` | one row per variable: deliverable? fit for a trend? | coverage overview |

`region` is a preset id (`"south_ukraine"`), a `Region`, or `[west, south, east, north]`. Presets with
`land_only: true` average land cells only.

## 6. Data rules (already enforced in code)

- **Area means** use cos(latitude) weights; `land_only` presets drop ocean, lakes and ice sheets.
- **Checks before any trend** (`assess`): ≥ 10 years and ≥ 120 months; every calendar month in
  ≥ 5 years; < 25% of observations in flat months or exactly zero; no gap > 12 months; not constant.
  Thresholds pending the stats lead (plan v2 also proposes ≥ 80% valid months).
- **Daily → monthly**: mean for states; mean × days for per-day fluxes; month kept if ≥ 80% of days.
  Checked: equals POWER's own monthly precipitation totals to 0.000 mm in all four case regions.
- **Known traps**, each documented in the catalog or methods:
  - monthly-store `T2M_MAX`/`T2M_MIN` are the month's hottest/coldest hour, 5–7 °C off the mean
    daily values: use `get_monthly_from_daily(..., how="mean")`
  - sea-ice fraction counts land as 0: value is the share of the whole box
  - SRB (to 2000) and SYN1deg (from 2001) must never be joined into one series
  - GRACE: gap 2017-07 → 2018-05; anomalies vs 2004–2009
  - MODIS NDVI: snowy and cloudy months dropped (Ukraine: 46 of 321)
  - HDF4 `scale_factor = 10000` in MODIS means *divide*
- **Boxes are fixed before results are seen.** No box, threshold or period is changed after looking
  at a trend.

## 7. Reproducibility

Every cached file has a provenance sidecar (source, version, DOI, bbox, period, access date, script,
git commit). **Resolved (B1-13):** the code is committed and the cache was regenerated from it
(sidecars cite b47dff5 / 95254d1, reachable from `main` via a real merge commit); the canonical
ukraine series were rebuilt land-only on 2026-11-14 (Q2).

Rebuild commands (PowerShell or bash, from the repo root):

```
python scripts/build_data.py            # every build.yaml job; --only ukraine for one preset
python scripts/region_inventory.py --region south_ukraine
python scripts/fetch_power_region.py --variable T2M --name Ukraine --bbox 22 44 40.5 52.5
python scripts/fetch_earthdata_region.py --dataset grace --name Ukraine --bbox 22 44 40.5 52.5
python scripts/fetch_earthdata_region.py --dataset ndvi --name Ukraine --bbox 22 44 40.5 52.5
```

**Resolved (B1-C1):** `scripts/build_data.py` rebuilds every series in `data/catalog/build.yaml` and rewrites `MANIFEST.json`.

## 10. Risks

| Risk | Effect | Mitigation |
|---|---|---|
| Network resets during fetches (seen several times) | interrupted downloads | retries, resumable NDVI, cache-first reads |
| Earthdata token expires (60 days) | no new NDVI/GRACE series | everything precomputed and committed; judging needs no token |
| Team changes regions late | new fetches needed | POWER series take seconds; NDVI ~7 min per region |
| Reanalysis read as observation by judges | Validity points lost | reanalysis sentence in each definition (T3); IMERG as satellite cross-check |
| Untested on Windows | teammates cannot run scripts | T8 |
